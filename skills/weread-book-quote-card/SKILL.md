# 微信读书金句卡片

输入书名，得到一张（或几张）3:4 的图片：上面是书的封面，下面是读者划线最多的几句话，
排成电影字幕条的样子。版式沿用"视频字幕拼图"的思路：主图约 70%，4 条字幕条各约 7.5%，条间距为 0。

这个 skill 分工明确：**脚本负责确定性的事**（取数、量字宽、断行、渲染、逐字核对），
**你负责需要判断的事**（确认是哪本书、挑哪几句、怎么分组、向用户解释）。

## 开始前

**Python 命令**：Windows 用 `python`，macOS / Linux 用 `python3`，后面一律加 `-X utf8`
（Windows 的输出编码默认不是 UTF-8，不加会在中文和特殊符号上出错）。下文写作 `<PY>`。
`<SKILL_DIR>` 指本 `SKILL.md` 所在目录的绝对路径，不要假设当前工作目录就是它。

**先做环境检查**：

```bash
<PY> -X utf8 "<SKILL_DIR>/scripts/check_environment.py" --network
```

它会报告 Python、Pillow、中文字体、API Key 是否设置、能否连上微信读书。缺什么就按它的提示说明用途，
取得用户同意后再装（`<PY> -m pip install -r "<SKILL_DIR>/requirements.txt"`）。不要擅自改系统设置。

**API Key 的规矩**（这是安全边界，不是建议）：
- Key 只放在环境变量 `WEREAD_API_KEY` 里，由用户在**自己电脑上**设置。
  获取方式：用户登录 https://weread.qq.com/r/weread-skills 取得形如 `wrk-` 开头的 Key。
- 不要让用户把 Key 发进对话，不要把它写进任何文件、命令行参数或日志。
- 如果用户已经把 Key 发进了对话，提醒他这个 Key 现在应当视为已暴露，建议回官方页面重新获取。
- 没设置时，把设置方法告诉用户：Windows PowerShell 运行 `setx WEREAD_API_KEY "wrk-你的Key"`，
  然后**完全退出并重新打开 Codex**才会生效。

**运行位置**：需要在用户自己的电脑上运行。网页版或受限沙箱连不上微信读书，这时如实说明，不要硬试。

## 流程

产物统一放在 `weread_cards/<书名>/` 下（用 `--out-dir` 改）。下文用 `OUT` 表示这个目录。

### 1. 确认是哪本书

```bash
<PY> -X utf8 "<SKILL_DIR>/scripts/weread_fetch.py" search "书名"
```

- 只有一个明显匹配（书名完全一致、作者吻合）：直接继续，并在回复里说一句选了哪本。
- 有几个都说得通（同名异作者、单本和全集、修订版）：把候选列给用户，**问一次**选哪本。不要替用户猜。
- 搜不到：请用户换个写法或补上作者。

### 2. 取封面和热门划线

```bash
<PY> -X utf8 "<SKILL_DIR>/scripts/weread_fetch.py" fetch --book-id <bookId> --out-dir "OUT"
```

生成 `OUT/book.json` 和 `OUT/cover.jpg`。留意输出里的封面像素：宽度小于 200 时成品里封面会偏糊，
要在交付时说明，并可以让用户手动提供更大的封面（渲染时用 `--cover`）。
热门划线最多 20 条，这是接口的上限，不是出错了。

### 3. 整理候选

```bash
<PY> -X utf8 "<SKILL_DIR>/scripts/prepare_quotes.py" --book "OUT/book.json" --out "OUT/candidates.json"
```

它会打印一张候选表：每条划线的**编号、热度（多少人划线）、字数、占几条字幕条**，
太长的划线下面列出能放下的"完整句子"选项（编号如 `14.3`），重复的划线会被标出，
末尾还有一份按热度凑数的"打包建议"。

### 4. 选句并分组（需要判断，先读 `references/selection-rubric.md`）

读完候选表和选句标准，决定做几张卡、每张放哪几句。把选择写成 `OUT/cards.json`：

```json
{"cards": [{"name": "孤独与时间", "quotes": ["1", "6", "14.3"]}]}
```

- 只写**编号**，不要自己重新打字。编号对应的文字由脚本填入，这是保证"原文不被改动"的关键。
- 每张卡的金句占条数加起来要**正好等于 4**（候选表"占条"一列相加）。
- 打包建议只是机械凑数，不是答案：它不看主题，也不会避开敏感内容。
- 默认只做**一张**最强的卡，用户要更多再加。

选完先给用户一句话预览（主题 + 每条金句和热度），不需要等确认就可以直接渲染，除非用户想先看。

### 5. 渲染

```bash
<PY> -X utf8 "<SKILL_DIR>/scripts/render_card.py" --book "OUT/book.json" --candidates "OUT/candidates.json" --cards "OUT/cards.json" --out-dir "OUT/cards"
```

渲染前它会先校验：编号是否存在、条数是否凑满、有没有重复、是否太长。报错时按提示改 `cards.json`。
默认不覆盖已有成品，需要替换时才加 `--overwrite`。
版式细节和可调参数见 `references/layout-spec.md`，只在需要调整时才读。

### 6. 质检并有界返工

```bash
<PY> -X utf8 "<SKILL_DIR>/scripts/qa_check.py" --manifest "OUT/cards/render_manifest.json" --book "OUT/book.json"
```

自动质检会重新核对：卡面文字与微信读书原始划线是否**逐字一致**、版面是否超出、封面放大倍数、
每条字幕条是否真有字。有 FAIL 就必须处理；WARN 要评估后在交付时说明。

**然后用眼睛看**：逐张打开成品图片，确认封面完整不变形、字幕条文字清晰、在手机缩略图大小下也读得出。
自动检查不能替代这一步。如果当前环境看不了图片，如实告诉用户"只做了自动检查，没有肉眼检查"，
请用户打开 `contact_sheet.jpg` 确认。

发现问题时**只改对应的那一个变量**（排障表在 `references/layout-spec.md`）。
连续三轮仍不满意，换一组金句或如实说明限制，不要无限微调。

### 7. 交付

告诉用户：成品图片的路径、总览图路径、每张卡里每条金句的编号和热度、
你放弃了哪些高热度句子以及原因、封面清晰度等任何 WARN。
没有逐张检查过的图片，不要说"完成"。

用户要发布时，提醒一句：内容来自微信读书，请自行确认使用条款，卡片上已保留书名、作者和来源标注。
用户需要配套的标题或文案时再写，不主动附送。

## 不能破的规则

- **卡面上的每个字都必须是微信读书的原文。** 不改写、不缩写、不合并、不"润色"。
  这是读书类内容的底线：读者看到的引文必须真是书里的话。只做断行，不做改字。
- **热度数字是真实数据**，只能照抄接口返回的人数，不能估算或美化。
- **不保存他人信息。** 接口返回的 `userVid` 不要读取、不要写进任何文件。
- **不覆盖用户已有的文件**，除非用户明确要求替换。
- **不让 Key 出现在任何地方**：对话、命令行、文件、日志、成品。

## 停止条件

出现这些情况时，停下来说明原因和选项，不要硬做：

- 没有设置 `WEREAD_API_KEY`，或网关返回 `-2012`（Key 失效）：请用户重新获取。
- 连不上 `i.weread.qq.com`（不在本机、被网络限制）。
- 搜不到书，或这本书没有热门划线（冷门书）。
- 能用的金句凑不满一张卡。如实告诉用户，可以放宽到 `--flex`（3–6 条）或换书，不要塞无关的话凑数。
- 没有可用的中文字体：请用户用 `--font` 指定一个有使用权的字体。
- 用户要把成品用于商业用途：说明版权和平台条款需要自己确认。
