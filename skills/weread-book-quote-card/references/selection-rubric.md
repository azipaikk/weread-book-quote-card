# 选句与分组标准

`prepare_quotes.py` 给出的"打包建议"只是按热度机械凑数。真正的选择要靠这里的编辑判断。
选句是这个 skill 里最需要判断力的一步：读者看到的不是数据，而是几句话组成的一张图。

## 目录
- 先回答一个问题
- 逐条筛选
- 分组成卡
- 不要这样选
- 怎样向用户说明

## 先回答一个问题

这张卡发出去，一个**没读过这本书**的人看到这几句话，会不会停下来？
热度告诉你"很多读过的人划了它"，但不保证没读过的人看得懂、愿意看。热度是第一道门槛，不是终点。

## 逐条筛选

按下面顺序过一遍候选表，每一条回答"是 / 否 / 勉强"：

1. **热度**：优先用热度靠前的。不要为了凑某个主题去选热度很低的句子；候选里本来就只有前 20 条，
   热度都不低。
2. **能独立成句**：抽离上下文仍然读得懂。剔除靠代词撑着的句子（"他说""那个地方""她笑了"而没说是谁），
   以及必须知道剧情才懂的人物对话。
3. **有嘴替感或洞察**：是否精准说出了一种大家有但说不出的感受（孤独、遗憾、释怀、衰老、爱而不得），
   或者给了一个反直觉的新视角。纯情节叙述（谁死了、谁到了哪里）即使热度高，通常也不适合做卡片。
4. **占条数合适**：看候选表"占条"一列。1 条 = 单行短句，2 条 = 两行。一张卡共 4 条，
   组合可以是 2+2、2+1+1、1+1+1+1。
5. **断行是否自然**：标"非标点断行"的句子，两行是在字中间断开的，可能把一个词拆开。
   渲染后看一眼；拆得难看就换一个，或者改取它的完整句子选项。
6. **敏感内容**：描写自杀、自残、严重暴力的句子，即使热度高也不要放进默认推荐，
   社交平台分享的场景不适合。要用也先告诉用户。

太长的划线怎么办：看它下面的 `3.1`、`3.2` 这样的编号，那是它的"完整句子"选项。
挑**单独读也成立**的那一句，不要为了凑条数选半截话。

## 分组成卡

- **一张卡一个情绪或主题**，例如一张全是"孤独"，另一张全是"时间与衰老"。组内的句子要读起来像一条线，
  而不是随机拼盘。
- **顺序**：默认按书中出现的顺序（候选表里的章节顺序）。如果有"铺垫 → 转折"的递进，可以调整，但要有理由。
- **首句最重要**：读者先看到卡片顶部第一条字幕条。把最有力、最完整的一句放在第一位，
  除非它要靠后面的句子收尾。
- **不重复**：同一条划线（或与它重叠的）不要出现两次；`prepare_quotes.py` 标了"重复于 N"的不要选。
- **默认只做一张最强的卡**。用户说"多做几张"再做第二张、第三张，不要一次交出七张让人挑。

## 不要这样选

- 只看热度排序，直接用"打包建议"。
- 改写、缩写、合并句子来让它更顺口。文字必须是原文，只能用候选表给的整句或完整句子选项（编号）。
- 为了凑满 4 条，塞进一句不相关的话。凑不满就如实告诉用户，换一个主题或者放宽条件。
- 把"我的看法"写进卡片。卡片上只有书里的话。

## 怎样向用户说明

交付时列出每张卡的：主题一句话、每条金句的编号和热度（多少人划线）、你放弃了哪些高热度句子以及原因
（太长、依赖上下文、内容敏感）。这样用户能快速判断，也能指挥你换一条。
